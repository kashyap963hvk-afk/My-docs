PART 6B - ADVANCED: Docker images, Compose, Kubernetes with Helm, deployment on FakeCloud and AWS EKS, CI/CD

6B.0 What, why, when

What: you pack QueryMesh into two Docker images, run the whole system with one Docker Compose command, then deploy it to Kubernetes with a Helm chart: first on kind (a free local Kubernetes on your Hyperstack VM, practised against FakeCloud), then on real AWS EKS behind an Application Load Balancer, with secrets synced from AWS Secrets Manager by the External Secrets Operator. Finally GitHub Actions tests, builds, pushes and deploys every change automatically.

Why: resume lines 10 and 11. "It works on my VM" is not production. Images make the app identical everywhere; Kubernetes restarts crashed pods and runs replicas; Helm makes the deployment one repeatable command; ESO keeps passwords out of Git; OIDC lets GitHub deploy without storing any AWS key.

When: after Part 6A works end to end (five agents + API + Gradio answering a question).

This part builds on: every file from Parts 4 to 6A, the .env file (Section 2B.8), vLLM and OpenSearch on the VM (Sections 2B.10 and 2B.11), FakeCloud and the AWS CLI (Section 2B.12).

SECTION 6B.1 - Create the Dockerfile and build the two images

WHERE: VS Code connected to the VM (Section 2A.10), Explorer panel, folder ~/querymesh

GOAL: two images on the VM: querymesh:v1 (API, 5 agents, Gradio, Telegram) and querymesh-ingest:v1 (the same + Docling for PDFs).

Step 1. Create the file Dockerfile (no extension, capital D) in the project root with the procedure from Section 2B.3.

Step 2. Paste this content and press Ctrl+S:

# Two images from one recipe:
#   docker build --target app    -t querymesh:v1 .          (API, 5 agents, Gradio, Telegram)
#   docker build --target ingest -t querymesh-ingest:v1 .   (adds Docling for PDF parsing)
FROM public.ecr.aws/docker/library/python:3.12-slim AS app
COPY --from=ghcr.io/astral-sh/uv:0.11.32 /uv /usr/local/bin/uv
ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1
WORKDIR /app
COPY pyproject.toml ./
COPY querymesh ./querymesh
RUN uv pip install --system --no-cache .
RUN useradd --create-home appuser
USER appuser
EXPOSE 8090 8101 8102 8103 8104 8105 7860
CMD ["uvicorn", "querymesh.api:app", "--host", "0.0.0.0", "--port", "8090"]

FROM app AS ingest
USER root
RUN uv pip install --system --no-cache torch torchvision --index-url https://download.pytorch.org/whl/cpu \
 && uv pip install --system --no-cache ".[ingest]"
USER appuser
CMD ["python", "-m", "querymesh.ingest", "--max-papers", "5"]

# so the containers reach them through host.docker.internal.

# One small OpenSearch node with security switched off (it is only reachable inside the cluster).
singleNode: true
protocol: http
opensearchJavaOpts: "-Xms1g -Xmx1g"
resources:
  requests: {cpu: 500m, memory: 2Gi}
persistence:
  enabled: false   # learning setup: data is re-loaded by the ingest CronJob after a restart
sysctlInit:
  enabled: true    # sets vm.max_map_count=262144 on the node
extraEnvs:
  - name: DISABLE_INSTALL_DEMO_CONFIG
    value: "true"
  - name: DISABLE_SECURITY_PLUGIN
    value: "true"
config:
  opensearch.yml: |
    cluster.name: opensearch-cluster
    network.host: 0.0.0.0
    plugins.security.disabled: true
Line(s)What it does (plain English)
singleNode: trueone OpenSearch machine instead of the chart's default of three (enough for learning)
protocol: httpplain HTTP inside the cluster (the security plugin is off, see below)
opensearchJavaOpts: "-Xms1g -Xmx1g"give OpenSearch 1 GB of Java memory (fits on a t3.large)
resources: requests: {cpu: 500m, memory: 2Gi}Kubernetes reserves half a CPU and 2 GB RAM for it
persistence: enabled: falseno disk volume: data is lost when the pod restarts. The ingestion CronJob refills it. For real production use a volume or Amazon OpenSearch Service (Part 7)
sysctlInit: enabled: truea small start-up container sets vm.max_map_count=262144 on the machine, which OpenSearch requires
DISABLE_INSTALL_DEMO_CONFIG and DISABLE_SECURITY_PLUGIN = "true"no demo certificates and no login. Acceptable only because OpenSearch has no Ingress: nothing outside the cluster can reach it
config: opensearch.yml: ...the OpenSearch settings file: cluster name, listen on all addresses, security plugin disabled
