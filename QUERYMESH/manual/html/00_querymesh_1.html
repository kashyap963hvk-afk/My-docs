PART 0 - Start Here

0.1 What QueryMesh is (in plain words)

QueryMesh is your own research assistant for arXiv, the website where scientists publish AI papers every day. You ask a question such as "How does reciprocal rank fusion combine keyword and vector search?" and QueryMesh answers in plain English, with numbered citations [1] [2] that link to the exact papers it used.

Behind the answer, a team of five small AI agents works together: a Retriever finds passages, a Grader throws away the useless ones, a Writer drafts a cited answer, a Critic checks every claim against the passages, and a Scout fetches brand-new papers from arXiv when the library has nothing good. A Supervisor decides who works next and retries when something is weak. Every night an Airflow job downloads new papers, Docling reads the PDFs, and OpenSearch stores them for hybrid search (keywords + meaning).

Why people build systems like this: a plain chatbot invents facts and knows nothing after its training date. Retrieval-augmented generation (RAG) gives the model fresh, checkable sources. Agentic RAG adds judgement: grade, retry, verify. Real-world use: research copilots (Elicit, Consensus, Semantic Scholar), internal company search assistants, legal and medical literature review, customer-support bots that must cite the manual.

0.3 What you will be able to do at the end

  • Build an ingestion pipeline: arXiv API -> PDF -> Docling Markdown -> chunks -> Jina vectors -> OpenSearch, scheduled daily by Airflow.
  • Run and explain hybrid search: BM25 keywords plus vector meaning, merged with Reciprocal Rank Fusion, and prove with numbers that it beats each method alone.
  • Build a LangGraph supervisor-worker system with five agents, a shared TypedDict state and an agentic RAG loop (retrieve, grade, rewrite, scout, write, critique, retry).
  • Expose every agent as a FastMCP server over SSE and as an A2A agent with an Agent Card, so agents discover each other and delegate work.
  • Trace every call with Logfire spans and every token with Langfuse, cache repeated questions in Upstash Redis, and protect the API with JWT.

1.2 Refreshers and 1-minute checks

Python. A dict maps keys to values; a list keeps order; a function returns a value. Check: what does this print?

paper = {"title": "RRF", "authors": ["Cormack", "Clarke"]}
print(len(paper["authors"]), paper.get("year", "unknown"))

Answer: 2 unknown

JSON. Text format: {} objects, [] arrays, strings MUST use double quotes. APIs send and receive JSON. Check: which line is NOT valid JSON?

{"question": "What is RAG?", "k": 5}
{'question': 'What is RAG?', 'k': 5}

Answer: the second (single quotes are Python, not JSON).

Terminal. pwd = where am I; ls = list files; cd folder = go into folder; cd .. = go up one folder; mkdir -p a/b = make folders; cat file = print a file. Check: after mkdir -p test/one and ls test you should see one.

Environment variables. A named value that every program started from this terminal can read. QueryMesh reads all its settings (keys, addresses) this way, from a file called .env. Check: type the two lines below in any Linux terminal; the second prints hello.

export GREETING=hello
echo $GREETING

HTTP APIs. A client sends a request (method, URL, JSON body); the server answers with a status code (200 OK, 401 not logged in, 422 invalid input, 500 server error) and JSON. Check: which code does QueryMesh return when you call /ask without a login token? Answer: 401.
