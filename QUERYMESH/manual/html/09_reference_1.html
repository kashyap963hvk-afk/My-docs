9.2 Back up

  • Code: GitHub (Section 2B.13). Push at the end of every session.
  • Secrets: keep a copy of .env in your password manager. Never commit it (it is in .gitignore).
  • OpenSearch data: it lives in the Docker volume opensearch-data. You can always rebuild it by running the ingestion again, so no backup is needed for learning.
  • Airflow settings: ~/airflow (re-created by airflow standalone if lost).

9.3 Update safely

  • Python packages are pinned in pyproject.toml. To update one: change its version, run uv pip install -e ".[dev,ingest]", run pytest -q, then try python -m querymesh.graph "test question".
  • Docker images: change the tag in scripts/start_vllm.sh or scripts/start_opensearch.sh, run the script again.
  • Kubernetes: build a new image tag (v2), run helm upgrade with --set image.tag=v2; roll back with helm rollback querymesh 1.

PART 11 - Practice Projects

11.1 Easy - Add a sixth agent: the Summariser

Goal: an agent that turns the final answer into 3 bullet points for Telegram.

Requirements: a new skill function, a new entry in AGENTS (port 8106) with its own Agent Card, a new node in the graph that runs after the critic says grounded, a test with a fake skill.

Success criteria: pytest passes; the Agent Card at port 8106 lists the skill; Telegram replies show the bullets; the supervisor still finishes in under 12 steps.

11.2 Medium - Semantic cache next to the exact cache

Goal: also reuse answers for questions that mean the same thing ("What is RRF?" and "Explain reciprocal rank fusion").

Requirements: store question vectors in a second OpenSearch index; on a cache miss, search it with k=1 and reuse the answer if similarity is above a threshold you choose; log hits in Logfire; keep the SHA-256 cache as the first, fastest check.

Success criteria: on 20 paraphrased questions, at least 50% hit the semantic cache, and a manual check of 10 hits finds no wrong reuse.

11.3 Hard - Production hardening on EKS

Goal: QueryMesh survives load and failures on EKS.

Requirements: HorizontalPodAutoscaler for the API and writer; PodDisruptionBudgets; HTTPS on the ALB with an ACM certificate; per-user rate limiting in the API; OpenSearch with persistent EBS storage; a GitHub Actions job that runs the Part 7 evaluation and fails the deploy if the grounded rate drops by more than 5 points.

Success criteria: a 10-minute load test at 5 requests/second with p95 latency under 30 s and no 5xx; deleting any one pod causes no failed request; the pipeline blocks a deliberately worse prompt.

ANSWER KEY

1. Supervisor -> retriever (few or no chunks) -> grader (fewer than 2 relevant) -> supervisor rewrites the query -> retriever -> grader (still too few) -> scout (fetches fresh arXiv abstracts) -> retriever -> grader -> writer -> critic -> finish. In remote mode the retriever may already ask the scout over A2A on its first call, because it found fewer than 3 hits.
