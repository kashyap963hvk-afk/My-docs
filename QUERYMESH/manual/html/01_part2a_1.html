PART 2A - Hyperstack GPU machine + SSH + VS Code + WinSCP (connection from zero)

BEFORE YOU START: what you are building in this part

Your laptop has no strong GPU, so you rent one. Hyperstack is a cloud company that rents computers with NVIDIA GPUs by the hour. You will: (1) install two programs on your laptop (VS Code and WinSCP), (2) make an SSH key (a digital key pair that lets your laptop log in securely), (3) rent a GPU computer ("VM" = virtual machine) on Hyperstack, (4) connect to it three ways: PowerShell (a terminal), VS Code (an editor that works ON the VM) and WinSCP (drag-and-drop files), and (5) learn port forwarding, so web pages that run on the VM (Airflow, Gradio) open in your laptop's browser.

WordPlain meaning
VM (virtual machine)a computer in a data centre that you control over the internet
SSHthe secure way to log in to a Linux computer remotely; it uses port 22
SSH key pairtwo files: the private key (stays on your laptop, never share) and the public key (.pub, you give it to Hyperstack)
public IPthe internet address of your VM, for example 38.80.123.45
environment (Hyperstack)a folder in Hyperstack that holds your VMs and keys in one region
flavor (Hyperstack)the hardware size: which GPU, how many CPUs and how much memory
image (OS image)the operating system installed on the VM; ours already has the NVIDIA driver and Docker
port forwardinga tunnel inside SSH: http://localhost:7860 on your laptop shows what runs on port 7860 of the VM

Result at the end of this part: VS Code on your laptop shows a terminal that says ubuntu@querymesh-gpu, nvidia-smi prints "NVIDIA RTX A6000", WinSCP shows /home/ubuntu, and a test web page on the VM opens in your laptop's browser.

SECTION 2A.4 - Create the SSH key on your laptop

WHERE: Windows laptop > Start menu > type PowerShell > click Windows PowerShell

GOAL: a private key file and a public key file in C:\Users\YOUR_NAME\.ssh

Step 1. Check that SSH is installed. Type and press Enter:

ssh -V

You should see: OpenSSH_for_Windows_9.x ...

Step 2. Create the key pair. Type and press Enter:

ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\hyperstack_ed25519 -C "querymesh"

Step 3. When it asks "Enter passphrase (empty for no passphrase)", press Enter.

Step 4. When it asks "Enter same passphrase again", press Enter.

You should see: "Your identification has been saved in C:\Users\YOUR_NAME\.ssh\hyperstack_ed25519" and a small square picture of random characters.

Step 5. Print the PUBLIC key:

Get-Content $env:USERPROFILE\.ssh\hyperstack_ed25519.pub

You should see: one line starting with ssh-ed25519 and ending with querymesh

Step 6. Select that whole line with the mouse and press Ctrl+C (copy). Keep PowerShell open.

SECTION 2A.8 - Wait for ACTIVE, copy the IP, check the SSH firewall

WHERE: Hyperstack console > Virtual Machines

GOAL: the VM is running and reachable on port 22.

Step 1. Wait until the Status column shows ACTIVE (usually 2-10 minutes; refresh the page).

Step 2. In the PUBLIC IP column, copy the address and paste it into secrets.txt as VM_IP = ...

Step 3. Click the VM name querymesh-gpu (the VM details page opens).

Step 4. Click the Firewall tab.

Step 5. Make sure Enable SSH access is ON.

Step 6. Under Inbound Rules, check there is a TCP port 22 rule with status SUCCESS.

Step 7. Click the Networking tab and find Connect over SSH: it shows a command like ssh ubuntu@38.80.123.45 (you add your key to it in the next section).

You should see: ACTIVE, a public IP, and the port 22 rule.

Watch out: do not add rules for 8000, 9200 or 8080. Those services have no password of their own or only an API key; you will reach them safely through SSH port forwarding (Section 2A.12) [5].

CHECKPOINT: you have VM_IP and the port 22 rule shows SUCCESS.

If not: no public IP = Networking tab > turn on Public IP Attached.

SECTION 2A.9 - First connection from PowerShell

WHERE: Windows PowerShell on your laptop

GOAL: log in to the GPU computer and see the GPU.

Step 1. Type (replace VM_IP) and press Enter:

ssh -i $env:USERPROFILE\.ssh\hyperstack_ed25519 ubuntu@VM_IP

Step 2. When asked "Are you sure you want to continue connecting (yes/no/[fingerprint])?" type yes and press Enter.

You should see: a welcome text and the prompt ubuntu@querymesh-gpu:~$

Step 3. Type and press Enter:

nvidia-smi

You should see: a table containing "NVIDIA RTX A6000", "49140MiB" (48 GB) of memory, "Driver Version: 570.xx" and "CUDA Version: 12.8".

Step 4. Check the disk space:

df -h /

You should see: the root disk / with at least 80 GB free. The vLLM image (about 10 GB), the model (about 8 GB) and the Python packages (about 8 GB) fit easily.

Step 5. Type exit and press Enter (you are back on your laptop).

SECTION 2A.10 - Connect VS Code to the GPU computer (Remote-SSH)

WHERE: VS Code on your laptop

GOAL: VS Code opens folders and terminals ON the GPU computer.

Step 1. Press F1 (a command box opens at the top).

Step 2. Type Remote-SSH: Open SSH Configuration File and press Enter.

Step 3. Click the first file: C:\Users\YOUR_NAME\.ssh\config

Step 4. Paste this at the end of the file (replace VM_IP and YOUR_NAME):

Host querymesh
    HostName VM_IP
    User ubuntu
    IdentityFile C:\Users\YOUR_NAME\.ssh\hyperstack_ed25519
    ServerAliveInterval 60

Step 5. Press Ctrl+S to save.

Step 6. Press F1.

Step 7. Type Remote-SSH: Connect to Host and press Enter.

Step 8. Click querymesh.

Step 9. If a box asks "Select the platform of the remote host", click Linux.

Step 10. Wait until the bottom-left corner shows SSH: querymesh (the first time VS Code installs a small server on the VM, about 1 minute).

Step 11. In the top menu click Terminal > New Terminal.

You should see: a terminal panel at the bottom with the prompt ubuntu@querymesh-gpu:~$

Step 12. In that terminal type hostname and press Enter.

You should see: querymesh-gpu

Line in the configWhat it means
Host querymesha short nickname you choose
HostName VM_IPthe real address
User ubuntuthe login name on Hyperstack Ubuntu images
IdentityFile ...which private key to use
ServerAliveInterval 60send a small "I am here" message every 60 seconds so the connection does not drop

Watch out: from now on, "VS Code Terminal" in this manual ALWAYS means this terminal connected to the GPU computer (bottom-left shows SSH: querymesh), not your laptop.

CHECKPOINT: hostname prints querymesh-gpu.

If not: F1 > Remote-SSH: Kill VS Code Server on Host > querymesh, then repeat Steps 6-10.

SECTION 2A.12 - Port forwarding: open VM web pages in your laptop browser

WHERE: VS Code (connected, bottom-left shows SSH: querymesh)

GOAL: a web page served on the VM opens at http://localhost:PORT on your laptop, with no firewall change.

Step 1. In the VS Code Terminal start a tiny test web server on port 8765:

python3 -m http.server 8765

You should see: Serving HTTP on 0.0.0.0 port 8765 (http://0.0.0.0:8765/) ...

Step 2. In the bottom panel click the PORTS tab (next to TERMINAL).

Step 3. Click Forward a Port (or the + button).

Step 4. Type 8765 and press Enter.

You should see: a row with Port 8765 and Forwarded Address localhost:8765.

Step 5. On your laptop, open the browser at http://localhost:8765

You should see: "Directory listing for /" with the files of /home/ubuntu.

Step 6. Back in the VS Code Terminal, press Ctrl+C to stop the test server.

Step 7. In the PORTS tab, right-click the 8765 row and click Stop Forwarding Port.

The ports you will forward later:

PortServiceSection
8080Airflow web UI4.8
8090QueryMesh API (/docs page)6A.7
7860Gradio web chat6A.9
8101-8105the five agents (Agent Cards)6A.3

Watch out: VS Code often forwards a port automatically when a program prints a localhost address; check the PORTS tab before adding it again. The forward only works while VS Code is connected.

CHECKPOINT: the directory listing opened in your laptop browser.

If not: if the browser says "connection refused", the server on the VM is not running (repeat Step 1) or the port number differs between Step 1 and Step 4.

SECTION 2A.13 - Stop paying: hibernate, restore and delete

WHERE: Hyperstack console > Virtual Machines > click querymesh-gpu

GOAL: no GPU bill while you are not working (do this EVERY time you stop).

Step 1. In the VS Code Terminal, check nothing important is running: type tmux ls (you learn tmux in Part 2B; "no server running" is fine).

Step 2. In the Hyperstack console, open the VM details page (click querymesh-gpu).

Step 3. Hover over the menu with three dots in the top-right corner.

Step 4. Click Hibernate this VM.

Step 5. In the dialog, leave "Keep Public IP attached?" OFF (cheaper; you get a new IP later) or turn it ON (small hourly charge, same IP).

Step 6. Click Hibernate this VM to confirm.

You should see: status HIBERNATING, then HIBERNATED.

Step 7. To work again: open the VM details page, hover over the three-dot menu and click Restore (wait for ACTIVE).

Step 8. If the public IP changed: put the new IP in HostName of C:\Users\YOUR_NAME\.ssh\config (Section 2A.10 Steps 1-5) and in the WinSCP site (Edit > Host name).

VM statusGPU billed?What is kept

SHUTOFF (Stop)YES, still billed [3]everything

After Restore, the Docker containers vLLM and OpenSearch start again by themselves (they use --restart unless-stopped). FakeCloud, Airflow and the agents do not: restart them with the commands in Part 9 (QM Parts 8-14 - Reference).

Watch out: "Stop" is NOT a money saver on Hyperstack. Use Hibernate this VM or Delete.

Watch out: restoring needs the same GPU flavor to be in stock; if it is not, try later. Push your code to GitHub often (Section 2B.13), so you can rebuild on a new VM if needed.

CHECKPOINT: when you finish a work session, the VM shows HIBERNATED.
