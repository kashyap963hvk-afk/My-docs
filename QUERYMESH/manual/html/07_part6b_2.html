name: querymesh-ci

on:

    branches: [main]

  test:

      - uses: actions/checkout@v7
      - uses: astral-sh/setup-uv@v7

    needs: test
    runs-on: ubuntu-latest

      - uses: actions/checkout@v7

SECTION 6B.16 - Common mistake at this level

Mistake: running a command against the wrong place. kubectl talks to whatever kubectl config current-context says, and the aws command talks to FakeCloud only while AWS_ENDPOINT_URL is set. People install on EKS while they believe they are on kind, or create "practice" resources in their real account and pay for them for weeks.

How to spot it: before every block of commands run kubectl config current-context; echo "${AWS_ENDPOINT_URL:-REAL AWS}". The two answers must match the column you are in. Add a monthly AWS budget alert (Section 2B.12) so a forgotten cluster is noticed within a day.

Second mistake: baking secrets into images or the chart. If a password appears in docker history querymesh:v1, in values.yaml or in Git, rotate it at once. Secrets live only in .env (VM), Secrets Manager (cloud) and the Kubernetes Secret.
